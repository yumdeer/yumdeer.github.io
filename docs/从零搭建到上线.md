# 从零搭建到上线：Astro SSR 摄影博客 + Cloudflare Workers + D1 + R2 完整指南

> 面向零基础读者。照着做，你将得到一个可以**在线管理内容**（传照片、写文章、传音乐）的个人网站，
> 免费额度内基本零成本，push 代码自动部署，改内容不需要重新部署。
>
> 本仓库（flowerdeer.cn / 张鹿溪摄影集）就是按这套流程搭起来的，文档里所有代码都可以在本仓库找到成品。

---

## 0. 先搞懂我们在搭什么

### 0.1 传统博客 vs 这套架构

| | 传统静态博客 | 本项目（SSR + 数据库） |
|---|---|---|
| 改内容的方式 | 本地写 Markdown → 重新构建 → 重新部署 | 打开网页后台直接改，**即时生效** |
| 图片音频存储 | 和代码一起打包进仓库 | 存在独立的对象存储（R2）里 |
| 数据存在哪 | 文件（Markdown/JSON） | 云数据库（D1） |
| 适合谁 | 会用命令行的人 | 网站主人自己（手机也能传照片） |

### 0.2 三个核心概念（用大白话）

- **Cloudflare Workers**：一个跑在全球服务器上的"程序托管平台"。你的网站代码（Astro SSR）跑在上面，访客自动连到离他最近的节点。免费版每天 10 万次请求，个人站根本用不完。
- **D1**：Cloudflare 提供的 SQLite 云数据库。存你的文章文字、项目列表、管理员账号密码（加密后）这些**结构化文字数据**。
- **R2**：Cloudflare 提供的对象存储（类似阿里云 OSS / 七牛）。存**照片、音频这类大文件**，按存储量计费，免费 10GB。

### 0.3 整体架构

```
访客浏览器
   │
   ▼
Cloudflare 边缘节点（全球就近）
   │
   ├─ 静态文件（CSS/JS/图标） ──► 直接返回（快）
   │
   └─ 动态页面（首页/文章/后台 API）
        │
        ▼
   Worker 里跑的 Astro SSR 代码
        │
        ├──► D1 数据库（读/写文章、项目、账号）
        └──► R2 存储（读写照片、音频文件）
```

### 0.4 一个重要认知（本项目踩过最大的坑）

**Cloudflare 有两套托管产品：Pages（旧）和 Workers（新）。**
2026 年起，Astro 官方的 Cloudflare 适配器（`@astrojs/cloudflare` v14+）**已经不支持 Pages**，
只支持 Workers。网上老教程说"部署到 Cloudflare Pages"，照做会得到一个全站 404 的空壳。
**全程认准 Workers 就对了。**

## 3. 四个关键配置文件（本仓库成品可直接参考）

### 3.1 `package.json` —— 声明依赖和命令

核心依赖（版本号以本仓库为准）：

```json
{
  "type": "module",
  "scripts": {
    "dev": "astro dev",
    "build": "astro build",
    "preview": "astro preview"
  },
  "dependencies": {
    "@astrojs/cloudflare": "^14.3.4",
    "@astrojs/mdx": "^8.0.3",
    "@astrojs/sitemap": "^3.7.4",
    "astro": "^7.3.6",
    "gray-matter": "^4.0.3",
    "marked": "^18.1.1"
  },
  "devDependencies": {
    "wrangler": "^4.151.0"
  }
}
```

- `gray-matter` + `marked`：后台写文章用 Markdown，存库、前台渲染。
- `wrangler`：Cloudflare 官方命令行工具，本地模拟数据库/存储、执行建表 SQL 都靠它。

### 3.2 `astro.config.mjs` —— 告诉 Astro 用 SSR 模式跑在 Workers 上

```js
import { defineConfig } from 'astro/config';
import cloudflare from '@astrojs/cloudflare';

export default defineConfig({
  // SSR 模式：页面在服务器上按请求渲染，内容从数据库实时读
  adapter: cloudflare({
    // 本地 npm run dev 时，自动模拟出 D1/R2（存在 .wrangler/state 目录），
    // 不用连云端就能开发调试 —— 小白福音
    platformProxy: { enabled: true },
  }),
  output: 'server',
  // ★ 换成你自己的正式域名（用于 sitemap、OG 分享卡片等）
  site: 'https://flowerdeer.cn',
});
```

### 3.3 `wrangler.toml` —— Cloudflare 部署配置（绑定数据库和存储）

```toml
name = "flowerdeer"                     # ★ 你的 Worker 名字，随意取
main = "@astrojs/cloudflare/entrypoints/server"   # 官方推荐入口，照抄不要改
compatibility_date = "2026-10-15"       # 照抄一个近期的日期
compatibility_flags = ["nodejs_compat"] # 允许用 Node.js 的 API，Astro 必需

# 静态资源目录：构建产物里没被 SSR 接管的文件（CSS/JS/图标）从这里直接返回
[assets]
directory = "./dist"
binding = "ASSETS"

# ★ 数据库绑定 —— database_id 换成你自己的（第 6 步创建后得到）
[[d1_databases]]
binding = "DB"                          # 代码里用 env.DB 访问
database_name = "flowerdeer"
database_id = "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"

# ★ 对象存储绑定 —— bucket_name 换成你自己建的名字
[[r2_buckets]]
binding = "R2"                          # 代码里用 env.R2 访问
bucket_name = "flowerdeer-media"
```

> **为什么 main 指向一个奇怪的路径？**
> 这是适配器 v14 的官方写法：指向 npm 包内的入口文件（构建时一定存在）。
> 如果写成 `dist/server/entry.mjs`，构建时会报"文件不存在"——因为构建开始时 dist 目录刚被清空。
> 构建完成后适配器会自动生成修正过路径的部署配置，`wrangler deploy` 会自动使用。

### 3.4 `src/db/schema.sql` —— 数据库表结构

本仓库的 [src/db/schema.sql](../src/db/schema.sql) 共 6 张表，作用一目了然：

| 表 | 存什么 |
|---|---|
| `users` | 管理员账号（密码用 PBKDF2 加密，绝不存明文） |
| `sessions` | 登录会话 token（7 天有效，HttpOnly Cookie） |
| `projects` | 摄影项目（侧栏分组） |
| `photos` | 照片记录（图片本体在 R2，这里只存尺寸/模糊占位图等元数据） |
| `articles` | 随笔文章（Markdown 正文） |
| `tracks` | 音乐曲目（音频本体在 R2） |

## 4. 核心代码结构（本仓库地图）

小白不需要从零写（Clone 本仓库即得），但要知道哪块是干嘛的：

```
src/
├── lib/
│   ├── db.ts          # D1/R2 访问层：所有页面统一从这里拿连接
│   ├── auth.ts        # 注册/登录/会话（PBKDF2 哈希 + token）
│   └── markdown.ts    # 文章 Markdown → HTML 渲染
├── middleware.ts      # 拦截 /admin/** 和 /api/admin/**，未登录跳登录页
├── db/schema.sql      # 建表 SQL（第 5 步要用）
├── pages/
│   ├── index.astro            # 首页（照片墙）
│   ├── project/[slug].astro   # 项目详情
│   ├── blog/                  # 博客列表 + 文章页
│   ├── api/                   # 后端接口（上传照片/音频、增删改查）
│   └── admin/                 # 管理后台界面
│       ├── setup.astro        #   首次初始化：创建管理员（仅空库时可用）
│       ├── login.astro        #   登录
│       ├── projects.astro     #   项目管理
│       ├── photos/[slug].astro#   照片管理（浏览器端压缩后上传）
│       ├── articles.astro     #   文章编辑器
│       └── music.astro        #   音乐上传管理
└── ...
```

**两个设计要点**（想自己改代码时需知道）：

1. **取绑定的方式**：v14 适配器删掉了老的 `locals.runtime.env`，统一从 `cloudflare:workers` 模块拿：
   ```ts
   import { env } from 'cloudflare:workers';
   const db = env.DB;  // D1
   const r2 = env.R2;  // R2
   ```
2. **R2 文件命名约定**（本仓库 `src/lib/db.ts` 底部的 `r2Key`）：
   - 照片：`img/{项目slug}/{照片slug}/full.webp` 和 `thumb.webp`
   - 音频：`audio/{slug}.mp3`

## 7. 创建云端资源（Cloudflare 控制台操作）

登录 https://dash.cloudflare.com ，以下全在网页上点选。

### 7.1 创建 D1 数据库

1. 左侧菜单 **Storage & Databases → D1 SQL Database → Create**
2. 名字填 `flowerdeer`（要和 `wrangler.toml` 的 `database_name` 一致），位置选离你近的（亚太）
3. 创建完成后，详情页能看到 **Database ID** —— 复制它，填进 `wrangler.toml` 的 `database_id`，然后 commit + push

### 7.2 生产库建表（重要！云端库是空的）

1. 进入刚建的数据库详情页 → **Console（控制台）** 标签
2. 把 `src/db/schema.sql` 的全部内容粘贴进输入框 → **Execute** 执行
3. 切到 **Tables** 标签，确认 6 张表都在

> 命令行党也可以用：`npx wrangler d1 execute flowerdeer --remote --file=src/db/schema.sql`（需要先 `npx wrangler login` 授权）

### 7.3 激活 R2 并建桶

1. 左侧菜单 **R2 Object Storage** —— 首次使用会提示 **Subscribe / 激活订阅**，
   需要绑一张信用卡/借记卡（**免费额度 10GB 内不扣费**，个人站很难超出；介意的话到这一步再决定）
2. **Create bucket** → 名字 `flowerdeer-media`（和 `wrangler.toml` 的 `bucket_name` 一致），位置选亚太

> **本地库和云端库是两个完全独立的数据库。** 本地传的照片不会自动出现在线上 —— 上线后要在后台重新传（第 9 步）。

## 8. 创建 Worker + 配置自动部署

### 8.1 创建

1. 左侧菜单 **Workers & Pages → Create → Workers 标签 → Import a repository（连接 Git）**
2. 首次会要求 **授权 GitHub**：跳转到 GitHub 页面 → 只授权你需要的仓库（All repositories 或指定仓库）
3. 回到 Cloudflare，选择你的仓库

### 8.2 构建配置（照抄）

| 配置项 | 填什么 |
|---|---|
| Project name / Worker name | `flowerdeer` |
| **Production branch** | **`main`**（★ 见下面 8.3 的坑） |
| Build command | `npm run build` |
| Deploy command | `npx wrangler deploy`（默认值，不用改） |
| Root directory | `/`（保持默认） |
| Environment variables | 加一条：`NODE_VERSION` = `22` |

点 **Save and Deploy**，等 1-3 分钟构建。

> **不需要在控制台手动绑定 D1/R2！** `wrangler.toml` 里声明的绑定会在部署时自动生效
> （构建日志会列出 `env.DB`、`env.R2` 等）。控制台手动绑定是老 Pages 时代的做法。

### 8.3 构建失败？先查这两个（我们真实踩过）

**坑 1：默认分支是 master**
如果你的 GitHub 仓库默认分支是 `master`（老习惯），Cloudflare 会去构建 master 分支，
报错 `Could not read package.json`。修复：
- Worker 详情 → **Settings → Builds → Production branch** 改成 `main` 并保存
- 注意：改完点 Retry 可能仍构建旧分支，最稳的办法是往 main 推一个新提交触发全新构建

**坑 2：看到 "Wrangler configuration file" 相关报错**
检查 `wrangler.toml`：`main` 必须是 `@astrojs/cloudflare/entrypoints/server`，
`assets.directory` 必须是 `./dist`，且**不要**在 build 脚本里删除 `dist/server/wrangler.json`
和 `.wrangler/deploy/config.json` —— 它们是部署链路的必要产物。

### 8.4 验证

构建成功后，Worker 详情页顶部会显示你的地址：`https://flowerdeer.<你的子域>.workers.dev`。
浏览器打开：
- `/` 首页正常渲染
- `/admin/setup` 显示"初始化管理员"页面

以后每次 `git push`，Cloudflare 自动重新构建部署（约 1 分钟），无需任何手动操作。

## 9. 绑定自己的域名（有域名才需要）

### 9.1 把域名接入 Cloudflare（NS 切换）

1. Cloudflare 控制台 **Add a domain（添加域）** → 输入你买的域名 → 选 Free 计划
2. Cloudflare 会分配两个 NS 服务器，形如 `mckinley.ns.cloudflare.com` / `yichun.ns.cloudflare.com`
3. 去你买域名的地方（如阿里云：域名管理 → DNS 修改）把 NS 改成这两个
4. 等待生效（几分钟到几小时不等，控制台会显示状态变成 Active）

### 9.2 清理旧 DNS 记录（如果域名之前指向别处）

**Custom Domain 不允许和已有记录冲突。** 你的域名如果之前指向 GitHub Pages /
Vercel 等，会有一堆旧记录。去 **DNS → Records**，删掉根域名（`@`）的所有
A 记录和 CNAME 记录、以及 `www` 的 CNAME。（TXT 之类的验证记录不挡路，可保留。）

### 9.3 添加 Custom Domain

1. Worker 详情 → **Settings → Domains & Routes → Add → Custom Domain**
2. 输入 `你的域名.com` → 确认（会自动创建所需的 DNS 记录和 HTTPS 证书）
3. 重复一次，添加 `www.你的域名.com`
4. 等 1-3 分钟激活，浏览器访问验证。HTTPS 证书全自动，不用管。

## 10. 上线初始化（最后一步！）

1. 打开 `https://你的域名/admin/setup`
2. 注册**生产管理员**账号（用你自己的邮箱 + 一个强密码）
   - `/admin/setup` 只在管理员表为空时开放，第一个注册的人就是管理员，之后自动关闭
   - 本地开发的账号和线上**完全无关**（两个独立的数据库）
3. 登录 `https://你的域名/admin`，建项目、传照片、写文章、传音乐
4. 全部完成 —— 🎉 你的网站正式上线了

## 12. 踩坑实录（按发生概率排序）

| # | 症状 | 原因与解法 |
|---|---|---|
| 1 | 部署到 **Pages** 后全站 404 | `@astrojs/cloudflare` v14 已不支持 Pages，只支持 Workers。删掉 Pages 项目，按第 8 步用 Workers |
| 2 | Workers 构建报 `Could not read package.json` | Production branch 默认拿了 master（旧分支）。改成 main（见 8.3） |
| 3 | 本地 build 报 `main field doesn't point to an existing file` | `wrangler.toml` 的 `main` 写成了 `dist/server/entry.mjs`。必须写 `@astrojs/cloudflare/entrypoints/server`（见 3.3） |
| 4 | Workers 部署报 wrangler configuration 相关错误 | build 脚本里删了 `dist/server/wrangler.json` 或 `.wrangler/deploy/config.json`。不要删它们 |
| 5 | 添加 Custom Domain 提示 `externally managed DNS records` | 域名下有旧 A/CNAME 记录。先去 DNS 记录页删掉再添加（见 9.2） |
| 6 | `npx wrangler login` 卡住 / 超时 | 本地网络访问不了 Cloudflare 授权接口（代理/防火墙）。改用浏览器操作控制台，或配置 API Token |
| 7 | R2 页面提示 Subscribe | R2 需先绑卡激活订阅（免费 10GB 内不扣费），见 7.3 |
| 8 | 线上后台登录不上 / setup 打不开 | 生产库没建表（7.2 漏做），或管理员已存在（setup 自动关闭，直接用 /admin/login） |
| 9 | 代码里 `env.DB` 是 undefined | `wrangler.toml` 没写 D1 绑定，或 binding 名字对不上；本地 dev 需要 `platformProxy: { enabled: true }` |

| R2 | 10GB 存储 | **注意**：高清照片很占空间，照片多的话建议后台压缩上传（本仓库照片管理页已内置浏览器端压缩，约 1-2MB/张）。超了约 $0.015/GB/月 |
| Custom Domain + HTTPS | 免费 | — |

唯一可能产生费用的是 R2 超出 10GB（需要先绑卡才会按量计费）。
