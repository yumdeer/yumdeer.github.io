# `/tree/` — 3D 四季场景页说明

一个纯前端（three.js r186 + Astro）的 3D 场景页，用来展示"同一天、不同地点"的风景。
整页只有 `src/pages/tree.astro` 一个文件（模型/贴图在 `public/` 下），没有后端依赖。

## 1. 场景与地区

页面内置 6 个地区，配置集中在 `tree.astro` 的 `REGION_SCENE`：

| id | 地区 | 场景要点 |
| --- | --- | --- |
| `hangzhou` | 杭州 | 湖面 + 湖心亭 + 无栏杆缓坡木栈桥 + 雷峰塔，山环单侧开口（另一侧留出地平线） |
| `sanya` | 三亚 | 海天相接、无山环，程序化椰林 |
| `shandong` | 山东 | 阔叶林 + 平原缓丘 |
| `lhasa` | 拉萨 | 布达拉宫坐落红山，一整面收分大白墙从山脚砌到宫前，底部雪城与沿街店铺 |
| `harbin` | 哈尔滨 | 针叶林 + 雪线 |
| `tromso` | 特罗姆瑟 | 高纬低日照、雪山 |

每个地区可配置：地形高度场、树种与密度、山环方位/开口角度（`openAz/openCore/openEdge`）、
天体升落、雾浓度、季节色板。

## 2. 可切换维度

- **地区**：下拉框 `#in-region`
- **季节**：春/夏/秋/冬，驱动 `foliageMaterial()` / `woodMaterial()` 的贴图调色与叶色
- **天气**：`#weather-pills`，可选实况（Open-Meteo，需要 `connect-src https://api.open-meteo.com`）或 `mock` 预设；
  实况拉取温度、云量、风速、降水，mock 用于离线/测试
- **时段**：太阳高度角决定天光、阴影与天体位置；`#in-hour` 默认取浏览器真实时间
  （2026-10 起，不再是硬编码 14:00），拖动滑块可手动覆盖

天气接口的 CSP 白名单在 `public/_headers`，新增外部接口时同步添加，否则线上会被拦截。

## 3. 资源

```
public/models/           # GLB 模型（树、亭、塔、宫殿、山体等）
public/textures/
  ├── grass/             # 草叶贴图
  ├── ground/            # 地表贴图
  ├── palm/  pine/  willow/   # 树种树皮/叶贴图
```

杭州垂柳贴图已全部从 PNG 转成 **WebP**（2026-10，`f8d922e`）：整页首屏体积 27.1MB → 16.5MB。
新增/替换贴图时一律用 WebP，不要再放回 PNG 原图。

模型加载统一走 `ensureModel()`：`loadGLB` → `attachSpeciesTextures` → clone → bbox 归一化
（`MODEL_SRC[k].height/spread`、`trunkFoot`）→ `rebuildTree()` 按材质名分类
（`/leaves|leaf|twigs?/i` 视为叶片）→ 季节调色 → `addTreeWind()` 挂风摆。

## 4. 程序化建模（不依赖 GLB）

有些近景元素用 GLB 反而假，改为代码生成：

- **椰树 `buildPalmTree()`**
  - 树干：30 环 × 14 段，半径带根部膨大；贴图为程序化叶痕环（`palmBarkTexture()`）
  - 叶冠：22 片羽叶 × 每米叶轴 15 对小叶（按叶长换算对数，保证长短叶密度一致），
    两列小叶沿叶轴上翻成 V 形叶槽；小叶末端自坠
  - 冠基：叶鞘 + 青椰果簇
  - 枯叶：3 片近垂直下垂的老叶，复用 `makeFrond()`，独立材质 `palm_dead`（不参与季节调色）
  - 侧视图/顶视图都不再是"弯纸片"
- **布达拉宫前的红山**
  - `cragify()`：逐顶点三段渐变（山脚草灌绿 → 山腰碎石褐 → 崖顶裸岩），
    外扩碎石裙让山体以缓坡接入草甸
  - 台地：`PROF` 分段线性剖面 + smoothstep；宫殿下方由台地 mask 削平，
    南坡则按模型台基逐级缓降（见下条 `apron(z)`）
- **布达拉宫模型（GLB 承担，按实景南立面建模）**
  - 模型源文件 `tools/blender/potala.py`（连同共用的 `bg_common.py` 一起入库；
    `tools/blender/` 是建模脚本的唯一真源，`~/blender-mcp` 只是 Blender 运行时，
    不要再往里放脚本副本），
    通过 Blender headless MCP 重新导出：`python3 ~/blender-mcp/mcp_server.py --exec "exec(open('~/yumdeer.github.io/tools/blender/potala.py').read())"`
    （雷峰塔 `pagoda.py`、亭子 `pavilion.py`、山环 `mountains.py` 同样在 `tools/blender/`）
  - 输出 `public/models/potala_palace.glb`，**改完必须先 `npm run build` 再重启 preview**，
    否则预览拿到的还是 `dist/` 里的旧模型
  - 模型单位：白墙墙顶 `z=0`、雪城台面 `z=-25.6`、裙墙到 `z=-40`；
    世界标高 ≈ `PLAT_Y - PAL_SINK + 1.2 * z`（`pal.scale = 1.2`）
  - **立面刻意不对称，不是镜像对齐**（用户明确指出的问题）：白宫是 4 块高度互不相同
    的体块——西端快速跌落（`z 15.4 / 19.8 / 23.4`），紧贴红宫两侧的肩部
    接近红宫高度的 88%（`pot_w_e` 到 22.9）。红宫偏左（`x -12.6..7.4`，约占白宫正面
    三分之一），正因为左右不对称，天空线才有实景那种"西陡东长"的错落
  - **每块本身是逐级退台的**（`facade` 表最后一列是级数 2/3，`TIER_SHARE` 决定层高占比）：
    越往上越窄越浅，全部收在下一级台面以内。实景白宫是一层层收进去砌的，
    一层的收进量在正视图上就是一道横向阴影带；做成一根直上直下的方柱时，
    四块并排就是四个白盒子，再多窗也压不住积木感。
    三条硬规则：
    1）**贴红宫的那条边不能收**（`pot_w_c` 的 `x1`、`pot_w_e` 的 `x0`），收进去会插进红宫体块（穿模）；
    2）收进量要按块宽设上限（`iw * 0.14`），窄块（贴红宫两侧只有 5~7 宽）收两级就收没了；
    3）**每一级都要有自己的窗排**（挂在该级 `z1` 下方），否则收进去的那几层是光板，退台反而更生硬
  - **前脸必须前后错开**（`yf -12.45 / -11.35 / -12.20 / -11.35`）：只把 `ztop` 错落、
    前脸共面时，正视图就是一整张白纸片——所有面法向相同、受光相同，只剩轮廓差异。
    相邻块轮流前探/后退约 1.0，交界处才会冒出竖向转角面，有实景那种层层砌上去的量感
  - **东翼是一条"坡顶"长墙**（`pot_w_east`，`x 12.4..35`，墙顶 `z 17.80 → 11.80`）：
    实景东翼不是几块平顶盒子，檐口是一条**连续斜降**的长斜线，窗跟着斜线一开间一扇
    排下去（13 列 × 2 排）。落差必须给到 6 米：只降 3.7 米时正立面上几乎是一条平线，
    整段东翼又变回一整块大白板。斜边玛带不能用 `Matrix.Rotation` 转出来——本项目里两次
    都把它转成"向上翘"、飞离墙顶；必须用「沿坡向量 `ew_u` + 坡面法向 `ew_n`」
    显式算 8 个角点
  - **东西两端各一座圆角收分角楼**（`pot_bastion_w` / `pot_bastion_e`）：实景两端都是
    圆弧转角，不是一刀切的直角；必须探出白宫正面与侧面才看得见，放在块体内部会被白墙吞掉
  - **台基是一整面收分白墙**（不是多级台地）：`bx=2.2` 只做轻微左右收分，
    `by=3.1` 的前后收分与 `apron(z)` 那条斜线严格绑定，**不能改**
  - 大白墙上那两道**斜降挡墙是连续的厚带子**（`pot_diag_ramp` / `pot_diag_ramp_w`），不是一级级踏步：
    曾经做成 9 级独立台阶（宽 2.6 / 间距 2.35），竖向间距远大于踏步厚度，
    远看是一串悬空的深色短横线；现在沿墙面斜线扫出 2.45 高的白挡墙 + 1.0 高的
    深色压边（`pot_diag_ramp_lip`），外挑 0.86，靠自阴影读出厚度。两端 y 必须各自按大白墙的
    收分求（`wyf(z)`），否则一端陷进墙里、另一端悬空。
    **方向是"V"不是"Λ"**：两段梯子的最低点在中间，往东西两端爬升；
    中间那片凹处并排立着三栋黄琉璃檐矮楼（`pot_mid_a/b/c`）。
    做成"Λ"（往中间升）方向就反了，中间也会空出一大片白墙。
    **东西两段刻意不对称**：东段 `x 11.8..30.0 / z -19.9..-6.2`（更长更缓、白墙用 `pot_white_b`），
    西段 `x -29.0..-12.4 / z -9.4..-21.3`（更短更陡）。做成严格镜像时正视图左右完全对称，
    一眼就是"算出来的"
  - **台基上不要画通长的深色横线**（用户明确纠正过两次："真实图片没有棕色的横线"、
    "这一个棕色线对齐的不对，实际场景就是小房子不是对齐的"）：
    实景大白墙是整片刷白的，加一条贯穿全宽的棕线会让立面变成"分层蛋糕"，
    比空着还假（`pot_wall_band_low` 已删除，不要再加回来）。
  - **大白墙顶是一排高低错落的小白房子**（`pot_wh_*`，约 24 栋）：实景那个位置
    是贴着白宫脚下站成一排的僧舍/办事房，每栋自带一道窄边玛檐，所以深色檐线是
    **一段段错开的短线**，绝不通长对齐。每栋的宽 `2.05~2.6`、高 `2.85~4.9`、
    进深 `2.55~3.2`、前脸 `y -13.10±0.3` 全按 8/6/5 组循环错开，约 1/4 的栋
    不开窗（仓库/封闭僧舍）。**高差必须够大**（≥2 米）：只差十几厘米时远景
    仍然连成一条线——之前用 5 段 `ring_seg` 拼"分段边玛带"就是这么失败的。
    台基上真正存在的深色只有这两处：这排房子的檐线、
    以及两条斜挡墙顶部的压边。西端那道水平台沿收边用**白色**，用深色远看是一道黑杠
  - **台基中段有两排小盲窗**（`pot_wall_blind_*`，`z=-9.6 / -6.2`，`0.52×0.72`、间距 2.75）：
    整面台基一点窗洞都没有时，远看就是一张白纸，梯子和房子再多也压不住那片空白
  - **所有横向元素都不许对齐**：白宫各块窗排的首排标高、排距逐块错开（`z0f` 偏移表）；
    雪城 14 栋的檐口高度、外挑、窗距逐栋抖动；中央三栋矮楼宽度/间距/墙顶各不相同；
    店铺的面宽、高度、进深位置按 4 组循环错开。只要有两块东西在同一标高上连成一线，
    正视图立刻回到"积木拼的"
  - **两档白**（`pot_white` / `pot_white_b`）：相邻块交替使用。实景各段白墙是历年分别
    重刷的，色差明显；全用同一个色号时，再多几何错落也会被"一片纯色"抹平
  - **雪城**：大白墙脚下 14 块高度错落的低白房（`pot_sh_*`），墙顶带边玛带 + 一排窗，
    把白墙下段挡住；再往南是最底层 12 间临街店铺（双扇深色橱窗 + 白色窗棂 +
    深红遮阳檐 + 暖黄灯箱 + 门口球灯），高度按 0/0.45/0.20/0.62 循环错开
  - **窗阵只在每层墙顶 2~3 排**，墙面下半截留白。早期从墙脚铺到墙顶，
    远看是"公寓楼网格"，是模型最假的一处，已删除
  - **横向展开 `XS = 2.75`（导出前统一后处理 `spread()`）**：实景正面宽:高 ≈ 3.6:1
    （照片实测 950px : 260px），而只按立面高度建模时模型只有 1.3:1。台基是"削山砌的"，
    墙顶必须接 `PLAT_Y`、墙脚必须接山脚，高度动不了，只能把宽度拉出去。
    三条硬规则：
    1）**必须以 x=0 为轴缩放**：每个体块各按自身包围盒中心变宽时，相邻块会互相插进去
    （白宫四块并排各自变宽 2.75 倍就叠成一坨），以 0 为轴才能保证接缝位置不动；
    2）由 `panel()` 生成的窗/窗套**只移位不拉伸**（`PANEL_OBJS` 记录），
    0.6 宽的窄竖窗拉宽 2.75 倍就成了一条横杠；窗台那条连续白条 `*_sill` 例外，要跟着整排变长；
    3）**窗数必须同比加密**：`win_row(dens=XS)` 把窗数乘同一个倍数、东翼开间数与店铺间数
    也乘 XS，否则整排窗会被摊稀
  - 场景侧要同步放大：`PLAT_X 44→122`、`apronX ss(56,47)→ss(140,126)`、
    山脊总长 `L 240→340`、`HILL_H 80→68`（宫殿顶 ≈74，山脊必须压在它下面）；
    山体位置从 `(-75,-290)` 挪到 `(-190,-360)`，否则宫堡会撑满画面右半边
  - **拉萨要撤掉山环最近一层 `mtn_near`**（`paintMtn()` 里 `hideNear`）：
    山环三层脊线在 262/398/574m，宫堡挪到 406m 后，最近的 262m 那层正好挡在
    镜头与宫堡之间，会在宫堡前面的草坡上冒出几座**灰色尖石**、把大白墙咬掉一块
    （用户问过"这个石头是哪里来的"）。只撤 `mtn_near`，背景仍由 `mtn_mid`
    （398m）+ `mtn_far`（574m）供着，宫堡前后层次反而更清楚
  - 红宫：`x -8..8`、`z -0.5..26`（展开后 `x ±22`、宽 ≈ 全宽 195 的 23%）。
    **是整组建筑最高的那一段**：正中一座又高又窄的红色主体，白宫东西两翼都比它矮，
    才有实景那个"中间一座红的立着、两侧白的层层跌下去"的天际线。
    宽度必须在建模坐标里收窄到 16——跟着主体一起被拉宽时红宫会变成 4:1 的红扁条，
    而实景红宫是 220:145 ≈ 1.5:1 的竖块（这是"不像"的头号原因）。
    前脸退到白墙墙顶立面之后（`y=-12.0` 对白墙顶 `y=-12.9`），底边埋到 -0.5 避开共面；
    左右各多 0.4 插进白宫体块（接缝共面会在远处闪）。
    收分 `bx=0.90 / by=0.45`；窗是**密网格**（9 排 × 30 列，`0.46×0.68`），
    窗框必须给 `sur=0.10`：用默认 0.40 连成一片白网格，红墙整个被吃掉；
    正面 `u=2.6` 有一条竖向金色窗带（`z 4.4..24.4`）
  - 金顶：红宫顶 **7 座等高一排**（建模宽 `w≈2.2` → 展开后 ≈6.05，`apex 28.26~28.55`）
    + 两侧白宫肩部各 1 个 + 东翼端头 1 个。
    实景就是一排几乎等高的金顶连成金色屋檐线；做成 4 座且高低差大时，远看是几个互不相连的金点。
    **宽度必须按"没被拉宽"的绝对尺寸给**：给 3.55 时展开成 9.8 宽，而 7 座之间中心距只有 6，
    整排会互相插成一坨金块；给 2.2 刚好让 7 座首尾相接。
    远景要读成"一排屋顶"而不是"几个金点"，靠三层做法：
    1）**三档金**：坡面 `pot_gold` / `pot_gold_dk` 交替（相邻屋顶一亮一暗，否则整排糊成一坨）、
    戗脊与正脊用高光金 `pot_gold_hi`、檐下再压一条 `pot_band` 暗线（`eave_band` 下移 0.15）；
    2）**平脊**：`roof_sampler` 的 `r_in` 必须 1.45（顶面约占屋顶宽 2/5），给 1.15 时远景缩成三角；
    3）**檐口高过边玛墙顶**：红宫 26.0 + 边玛 1.05，所以 `z_eave` 给 26.45，给 26.0 时整个檐口
    埋在深色墙带里，只剩一个金色尖。
    **必须压在前檐口上（`cy ≈ -10`）**，放到纵深中部会被 26m 高的红墙从低机位完全挡住
  - **颜色按照片取色，并在场景里校正**：GLB 反照率（linear）白 `0.975/0.930/0.750`、
    红 `0.500/0.022/0.012`、边玛 `0.095/0.030/0.017`、金 `0.980/0.420/0.010`、
    窗洞 `0.030/0.012/0.010`；实景目标 sRGB 白 `#EDEAE2`、红 `#A32A22`、金 `#D9A63C`。
    实测渲染值（拉萨 14:00 晴）白 `#E4E6E2`、红 `#931F33`、金 `#CC9E41`（金顶像素中位数，
    含坡面暗档；脊线亮档更接近 `#D9A63C`）
  - **逆光补光 + 专用正面光 + 关雾**（`tree.astro` 的 `potalaMats` / `palLight`）：
    太阳方位角公式决定正午太阳在 −z，宫殿南立面**永远逆光**，只靠天光会是 `#89A0A5` 的冷灰蓝。
    因此给这套材质加 emissive，并按材质名给不同权重 `k`
    （white/sill 0.30、gold_hi 0.95、gold 0.48、gold_dk 0.34、red/band 0.42、amber 0.30、bush 0）——
    但 emissive 只能"兜底不让它发灰蓝"，**不能承担主要亮度**：之前 white 给 1.0 时，
    整面白墙是均匀自发光，所有朝向的面亮度几乎一样，凸出体块/窗洞/斜挡墙的明暗全被抹平，
    成品就是"渲染得太平整"。
    真正的亮度改由 `palLight`（`DirectionalLight`，位置 `(72,40,108)`，暖白）提供，
    它通过 `layers` 只作用于宫殿（光源 `layers.set(1)`，宫殿 mesh `layers.enable(1)`），
    并**开启阴影**（`shadow.camera` 取 ±52 / ±48）：正面几乎全是 +z 法向的面，
    不开阴影时方向光只是把整面墙点亮，只有让体块互相投影才有纵向层次。
    强度 `1.05 * daylight * 天气系数`；emissive 强度 `0.06 + 0.55 * daylight * 天气系数`，
    夜里收敛到 0.06（否则宫殿会在夜空里发亮）。
    金顶仍必须**按档分开补光**：三档都给同一个值时，四个坡面的亮度被 emissive 拉平，
    几何上的明暗全被抹掉，远景金顶就退化成一个金色色块。
    同时 `mat.fog = false`：场景雾是 `#88aacc`，在这个距离吃掉约三分之一，
    会把朱红压成粉紫、金顶压成土黄；实景照片里宫殿本身清晰，只有背后雪山是雾
  - **防 z-fighting 的两条硬规则**（否则远处会看到红色墙面在闪）：
    1）`manika()` 的边玛墙顶面必须比墙顶高 0.03，不能与下方墙体顶面共面；
    2）红宫底边要收在白宫台面以内（前脸比白宫外凸 0.45 即可，不能压在台沿上），
    否则两面近乎相切，远看是一条抖动红线
- **红山南坡缓台（`apron(z)`）**
  - 白色台基是"削山砌出来"的，山脚不留红土台地：坡面必须让出对应高度，
    否则台基要么整块埋进崖壁、要么悬在半坡
  - 现状：`z <= 32.2` 维持 `PLAT_Y = 40.5` 的平台，`32.2 → 36.1` 线性降到 `9.1`，
    再往外接自然坡；降坡段略偏在挡墙北侧，被模型自己的白色台面盖住，
    成品才不会出现"地形啃白墙"的锯齿
  - `apronX = ss(140, 126, |x|)` 把缓台横向铺满整个台基宽度（台基半宽 37.5×2.75×1.2 ≈ 124），
    超出后还原成岩壁；缓台范围内关掉 `rockN` 噪声
  - `NV` 从 46 提到 240：竖向网格太粗时，缓台会被插值成一片斜板
  - 早期在 `tree.astro` 里手搭的梯道/小房已全部删除，改由 GLB 提供，避免重复

## 4.5 湖心亭与栈桥（杭州，2026-10 定稿）

栈桥 + 亭子的全部逻辑在 `tree.astro` 的 `const woodMat` 那一段（约 4400 行起）。
最终形态是用户逐版截图确认出来的，**不要回退到下面这些历史方案**。

### 当前几何

- `WATER_Y = -0.55`；水面是 `CircleGeometry(292)`（早期 260 太小，湖盆边缘
  `e≈1.05~1.1` 的地面已低于水面却没水覆盖，露出"干的水下地"，看起来像亭子被搬上岸）。
  `inWater('hangzhou') = e < 1.02 || (e < 1.12 && groundY < WATER_Y)`，两处要一起改。
- 岸线搜索：从 `(-45,-34)` 沿 `(13,11)` 方向步进，取第一个 `groundY > WATER_Y + 0.02`
  的点作为水线 `(sx,sz)`。
- 亭子 `P` 在离岸 20m 的水面上；`pav.position.y = deckY - 0.27`（GLB 原点在台基底面中心、
  台基高 0.45m），台基底约 `-0.42`，**始终在水面之上**，不要再往下压。
- 桥面：`deckY = WATER_Y + 0.40`（板中心），板宽 2.6、厚 0.22，亭子端桥面顶 ≈ `-0.04`。
- **纯平接岸（用户明确要求"不要台阶"）**：没有任何台子/台阶。桥头端点向岸上多延 0.8m，
  `endY = groundY(端点) - 0.11 - 0.03`（桥面顶与地面同高、再压 3cm 埋进草里）；
  各跨高度按**累计路径长度线性插值**到 `deckY`，整条桥是约 2% 的均匀缓坡，
  跨与跨之间没有折角。
- **桥面无栏杆、无立柱**（用户要求）；亭子自身的围栏在 GLB 模型里，不受影响。

### 旋转的坑（踩过两次，别再踩）

三维对齐全靠 `deck.rotation.set(pitch, ang, 0, 'YXZ')`，其中
`ang = atan2(dx,dz)`、`pitch = -atan2(dy, flat)`：

1. **不能用 `Quaternion.setFromUnitVectors(+Z, dir)`**——最小旋转会把板宽方向一起拧歪，
   桥面看着像"翻了一块"。
2. **pitch 必须取负号**：three.js 的 `R_x(θ)` 把局部 `+Z` 转到 `(0,-sinθ,cosθ)`，
   符号写反时靠岸那跨朝反方向倾斜，和相邻跨错开一层（"桥面分成了两截"）。

### 已被用户否掉的方案（不要回退）

- 88m / 45m 长堤式栈桥：太长，亭子只要离岸 20m。
- 桥头"顶面齐平的落地木台"（`d6b4893`/`4bd6ee2`）：能消除断层，但木台凸出草坡，
  视觉上仍是一个台阶，已被纯平缓坡方案取代。
- 桥头压到水面以下（`tipY = groundY - 0.32` 之类）：桥头直接泡水，"像沉了"。
- 桥面带栏杆：已按要求删除，不要再加回。

## 5. 渲染要点

- **山环单侧开口**：`injectSnowGold()` 注入 `uOpenDir / uOpenCos / uCityMask`，
  按方位角把山脊压平，实现"一侧环山、另一侧开阔"（杭州原有效果不变）
- **天体**：太阳为硬边圆盘；月亮位置与相位由本地低精度历表计算（不依赖网络），
  天气只影响云量与可见度
- **性能**：叶片/山体均按地区合并几何；远距离元素不做逐帧更新

## 6. 本地开发

```bash
npm run build                # 产出 dist/
npx astro preview --port 4334  # 预览构建产物（改了代码必须重新 build 再重启，否则拿到旧 chunk）
```

调试截图脚本可放在 `/tmp`（Playwright），按地区切 `#in-region` 后截图，检查控制台 `errors`。
本项目实际使用的 `/tmp/shot-tree.mjs` 模式：Chromium 启动参数
`--use-gl=swiftshader --enable-unsafe-swiftshader`，`networkidle` 后等约 11s 让 GLB/贴图就绪；
局部放大用 `browser.newPage({ deviceScaleFactor: 5~8 })` + `page.screenshot({ clip })`
（clip 坐标是 CSS 像素，不是截图像素）。近景检查栈桥/亭子时，默认机位下亭子周围
`clip {x:110,y:320,w:330,h:130}`、桥头 `{x:300,y:370,w:260,h:150}`（1280×800 视口）。
OrbitControls 在 Playwright 里滚轮/拖拽基本无效，需要换机位时临时加
`?cam=x,y,z,tx,ty,tz` URL 钩子直接写 `camera.position` / `controls.target`，**用完删掉再构建**。

**重启 preview 必须走 `npx astro preview stop`**：直接 `pkill` 或让旧进程留着时，
新进程只会打印 "Another astro preview server is already running" 然后退出，旧进程继续
用**旧的 dist** 服务，`/models/*.glb` 甚至直接返回 500——看起来就像"改了没生效"。
重启后先核对一次：`curl -s http://127.0.0.1:4334/models/potala_palace.glb | md5sum`
必须等于 `public/models/potala_palace.glb` 的 md5。浏览器侧记得 Ctrl+Shift+R 强刷。另外不要 `pkill -f "astro preview"`：
匹配模式会把自己的 shell 也杀掉（命令以 exit -1 收场），用 `npx astro preview stop`。

### 线上部署与复核

push `main` → Cloudflare Workers Builds 自动构建，约 40~120s 生效。复核方式
（比"打开看看"可靠，因为 `_astro/*` 是 immutable 强缓存）：

```bash
ls dist/client/_astro | grep '^tree'                 # 本地新 chunk 名（内容寻址 hash）
curl -s https://flowerdeer.cn/tree/ | grep -o '/_astro/tree[^"]*\.js' | head -1
# 两边 hash 一致即说明线上已在跑新构建；不一致就等 20s 再查
```

注意 `/tree/` 是独立 `<head>`，不经过 `Layout.astro`：favicon / apple-touch-icon
要在 `tree.astro` 里单独声明（2026-10 修复过，缺了会退回浏览器默认图标并请求
不存在的 `/favicon.ico`）。新增独立 head 的页面同理。
